# 競馬予想ソフト 企画案

## おまけ: インベーダーゲーム

`invaders/index.html` をブラウザで開くだけで遊べる (インストール不要)。

- 操作: `← →` / `A D` で移動、`SPACE` で発射、`ENTER` でスタート、`P` で一時停止、`M` で音の切替
- スマホではタッチ用のボタン (◀ ▶ 発射) が画面下に出る
- 得点: 上段 30 点、中段 20 点、下段 10 点、UFO は撃った弾数で 50〜300 点。1500 点で砲台が 1 台増える
- ハイスコアはブラウザに保存される

## Windows での使い方 (ダブルクリック)

1. [Python](https://www.python.org/downloads/) 3.10 以上をインストールする
   (最初の画面で **Add python.exe to PATH** にチェック)
2. このリポジトリを取得する (GitHub の「Code → Download ZIP」で展開するか `git clone`)
3. フォルダ内の **`setup.bat`** をダブルクリック (初回のみ。ライブラリの導入・仮データ作成・学習を行う)
4. **`start.bat`** をダブルクリックするとブラウザで画面が開く。終了は黒い画面を閉じる

同じ Wi-Fi のスマホからは、起動時に表示される `Network URL` (`http://192.168.x.x:8501`) で開ける。

## 使い方 (Phase 1〜2 実装済み)

CSV 取込 → SQLite 保存 → 特徴量生成 → LightGBM で単勝勝率を予測 → 市場オッズと合成して確率を較正
→ 期待値・ケリー基準で買い目と金額を提案 → ウォークフォワードでバックテスト → CLI / Web UI で表示。

```bash
pip install -e '.[dev,ui]'

# 1. データ投入 (実データが無い場合は仮データで開発できる)
keiba sample                               # 仮データ (最終開催日は結果未確定) を data/keiba.db に投入
keiba import races.csv entries.csv         # 実データの取り込み

# 2. 検証
keiba evaluate --test-start 2026-01-01     # 指定日より前で学習し、以降で精度を評価
keiba backtest --start 2026-01-01 --save-preds preds.csv   # 月ごとに再学習しながら買い方を検証
keiba backtest --load-preds preds.csv --ev-threshold 1.3 --flat 100   # 再学習せず買い方だけ変えて再試行

# 3. 全期間で学習して models/win_model.pkl に保存
keiba train

# 4. 予測 (既定: 結果未確定の直近開催日)
keiba predict --bankroll 100000            # 推奨購入額つき
keiba predict --date 2026-10-24 --output pred.csv

# 5. Web UI (レース予想 / レース実況 / バックテスト / モデル評価)
streamlit run app.py
```

### 予測と買い方の仕組み

1. **モデル単体の勝率**: LightGBM (1着か否かの二値分類) の出力をレース内で合計 1 に正規化。
2. **較正**: 学習期間の末尾 20% を取り分け、モデル勝率と市場確率 (オッズの逆数を正規化) を
   条件付きロジット `p ∝ exp(a·log p_model + b·log p_market)` で合成 (Benter 方式)。
   `--no-market` でオッズを使わない温度スケーリングのみにもできる。
3. **買い方** (`keiba/backtest.py` の `Strategy`): 期待値 `勝率 × オッズ` がしきい値を超え、
   勝率下限・オッズ上限を満たす馬を、ケリー基準の一部 (既定 0.1 倍) か定額で買う。
   1 点・1 レースあたりの上限 (資金の 1% / 3%) あり。

### レース実況画面

Web UI の「レース実況」タブで、上から見たコース図を馬が走るアニメーションと、自動生成の実況テロップを表示する
(本物のレース映像ではない)。

- **予想シミュレーション**: 予想勝率から着順を抽選し、脚質 (過去の上がり順位から推定) に応じたペースで走らせる。
  「もう一度走らせる」で別の展開になる。1,000 回走らせたときの勝利数も表示
- **結果リプレイ**: 確定済みレースの走破タイムと上がり3Fから各馬の動きを再現
- 枠色の馬、左回り / 右回り、残り距離、現在の順位と着差、ゴール後の着順と推奨馬券の的中表示
- ブラウザの音声読み上げで実況をしゃべらせることもできる (「実況を読み上げる」にチェック)
- 位置取りは「前半は一定ペース、残り600mから上がり3Fのペース」の近似。
  JRDB のコーナー通過順位などを取り込めば実際の位置取りに近づけられる

### 仮データについて

`keiba sample` の仮データは、市場 (オッズ) が現実に近い強さになるよう調整してある
(詳細は `keiba/sample_data.py` 冒頭):

- 人気別の単勝回収率: 全体 約78%、1番人気 約80% (JRA の実績に近い値)
- 市場はモデルに見えない「当日の調子」を一部知っている一方、距離・道悪の適性は十分に織り込んでいない
- その結果、LogLoss は「モデル単体 (約0.23) > 市場 (約0.213) > 合成後 (約0.209)」の順 (小さいほど良い)

仮データ (200 開催日) でのバックテスト例: 2026年1〜10月、期待値 > 1.2・ケリー 0.1 倍で
376 点・回収率 約112%・最大ドローダウン 約27%。**この数字は仮データの設定次第で変わるもので、
実データで同じ成績が出ることを意味しない。**

### CSV の形式

- `races.csv`: `race_id, date, course, race_number, surface, distance, track_condition, race_class`
- `entries.csv`: `race_id, horse_id, horse_name, jockey_id, trainer_id, frame_number, horse_number, sex, age,
  weight_carried, horse_weight, horse_weight_diff, odds, popularity, finish_position, time_sec, last_3f`
- 必須列は races が `race_id, date, course, surface, distance`、entries が `race_id, horse_id, horse_number`。
  出馬表 (未確定レース) は `finish_position` などを空欄にする。
- 列の定義は `keiba/db.py` を参照。`keiba sample --csv-dir out/` で見本の CSV を出力できる。

### 現時点の制約

- オッズは「確定オッズ」を使っている。実際に買う時点のオッズは締切直前まで変わるため、
  実運用では購入直前のオッズで再計算する必要がある (バックテストの回収率は楽観的になりやすい)。
- 自分の購入によるオッズの低下は考慮していない。
- 券種は単勝のみ (馬連・三連複などは Phase 3)。

## 1. コンセプト

「当てる」より **「長期的に回収率100%超を目指す」** ことを主目的とした、データ駆動型の競馬予想支援ソフト。
的中率ではなく **期待値 (予測勝率 × オッズ)** を軸に買い目を提案する。

- 対象: JRA 中央競馬（将来的に地方競馬 NAR へ拡張）
- 利用者: 個人の競馬ファン（データ派〜初心者）
- 形態: まずはローカル動作する Python アプリ + Web UI

---

## 2. 主要機能

| # | 機能 | 概要 |
|---|------|------|
| 1 | データ収集 | 過去レース結果・出馬表・オッズ・馬場状態を取得し DB に蓄積 |
| 2 | 特徴量生成 | 馬・騎手・調教師・血統・コース適性などを数値化 |
| 3 | 勝率予測 | 機械学習モデルで各馬の勝率／複勝率を推定 |
| 4 | 期待値計算 | 予測確率 × 現在オッズ で期待値を算出し「妙味馬」を抽出 |
| 5 | 買い目提案 | 単勝・複勝・馬連・ワイド・三連複などの推奨買い目と資金配分 |
| 6 | バックテスト | 過去データで戦略をシミュレーションし回収率・最大ドローダウンを検証 |
| 7 | 収支管理 | 実際の購入履歴を記録し、戦略別の成績を可視化 |
| 8 | 予想根拠の表示 | 「なぜこの馬が評価されたか」を特徴量の寄与度 (SHAP) で説明 |

## 3. 予測に使う特徴量（例）

**馬**
- 直近 N 走の着順・着差・上がり3F・走破タイム（馬場・距離で補正したスピード指数）
- 距離／コース（芝・ダート、右・左回り、競馬場別）適性
- 馬場状態（良・稍重・重・不良）別成績
- 休養明け日数、叩き何戦目、馬体重とその増減
- 斤量、年齢、性別

**人**
- 騎手の勝率・複勝率（コース別・直近期間）、乗り替わりの有無
- 調教師の成績、厩舎の休み明け成績

**血統**
- 父・母父系統の距離／馬場適性

**レース条件**
- 枠番・馬番（コース別の枠有利不利）、頭数、クラス、ペース予測（逃げ・先行馬の数）

**市場情報**
- 単勝オッズ・人気（※モデル入力に入れるか、期待値計算のみに使うかは要検証）

---

## 4. 予測モデル

1. **ベースライン**: ロジスティック回帰（勝つ/勝たない）
2. **本命**: LightGBM
   - `LGBMRanker`（レース内での順位学習, LambdaRank）
   - もしくは二値分類 → レース内でソフトマックス正規化して勝率化
3. **確率の較正**: Isotonic Regression / Platt Scaling で、予測確率が実際の勝率と一致するよう調整
   （期待値計算の精度はここで決まる）
4. **組み合わせ馬券の確率**: 単勝確率から Harville モデル（または改良版）で馬連・三連複等の確率を算出

**評価指標**: LogLoss、AUC、的中率、**回収率**、最大ドローダウン
**検証方法**: 時系列分割（未来のデータで学習しない）。リーク防止に特に注意。

---

## 5. 買い目・資金配分ロジック

- 期待値 `EV = 予測確率 × オッズ` が閾値（例: 1.1）を超える馬券のみ購入
- 資金配分は **ケリー基準の分数版（1/4 ケリーなど）** で過剰投資を防ぐ
- 1 レース・1 日あたりの上限額を設定
- 締切直前のオッズ変動で EV が変わるため、直前再計算機能を用意

## 7. 画面イメージ

1. **本日のレース一覧**: 各レースの「妙味度」スコアを表示、注目レースをハイライト
2. **レース詳細**: 出走馬ごとの予測勝率・オッズ・期待値・印（◎○▲△）、根拠グラフ

5. **収支ダッシュボード**: 月別収支、券種別成績

## 9. 差別化アイデア

- **LLM 活用**: 調教師・騎手コメントや記者の短評をテキスト解析し特徴量化
- **「見送り」推奨**: EV が低いレースは「買わない」ことを明示し、無駄打ちを減らす
- **自分専用モデル**: ユーザーの好む券種・リスク許容度に合わせて戦略を最適化
- **予想の透明性**: ブラックボックスにせず、根拠を自然言語で要約して表示

---

## 10. 注意事項・リスク

- **控除率の壁**: JRA の控除率は約 20〜30%。人気順に買うだけでは回収率 75〜80% 前後に収束するため、市場（オッズ）より正確な確率推定が必須
- **データ取得の規約**: スクレイピングは各サイトの利用規約・robots.txt を遵守。安定運用には JRA-VAN などの公式データ提供サービスを利用する
- **過学習とデータリーク**: 未来情報（確定オッズ・レース後の情報）の混入に注意
- **自動投票**: 即 PAT 等への自動投票は規約確認が必要なため、初期段階では「提案のみ」とする
- **責任あるギャンブル**: 予算上限設定・損失アラートを機能として組み込む
